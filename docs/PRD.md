## 1. 배경과 문제

Paper Curation에는 검증된 논문 처리 기능이 있지만, 과거 운영 흐름은 특정 주제·기관·코퍼스·로컬 환경과 결합되어 있었다. 사용자는 자신의 Zotero 자료를 신뢰할 수 있는 리뷰와 로컬 페이지로 만들고 싶지만, 암묵적 기능 활성화, 공급자 대체, 불명확한 산출물 출처, 빌드와 공개 배포의 혼동은 안전한 범용 사용을 막는다.

## 2. 비전

사용자는 자신의 워크스테이션에서 자신의 Zotero 자료와 로컬 PDF를 사용해, **명시적으로 선택한** 리뷰 공급자로 검증 가능한 로컬 논문 페이지를 생성한다. 추가 분석, 외부 API 호출, 공개 배포는 사용자가 명시적으로 선택할 때만 수행된다.

제품의 최소 완성 단위는 다음과 같다.

> 선택한 논문 → 정확한 PDF → 추출 텍스트 → 선택한 공급자의 리뷰 → 근거 정보 → 열 수 있는 로컬 논문 페이지 → 검증 가능한 실행 기록

메타데이터만 있는 페이지, 빈 리뷰, 부분 산출물, 또는 실패를 숨긴 대체 결과는 성공이 아니다.

## 3. 사용자

- **로컬 연구자:** Zotero의 논문을 구조화된 리뷰와 로컬 페이지로 만든다.
- **연구팀 운영자:** 주제별 코퍼스를 관리하며 비용, 실패, 산출물 출처와 공개 행위를 통제한다.
- **통합 개발자:** 새로운 자료원·리뷰 공급자·추출기·배포 수단을 제품 계약 안에서 추가한다.

## 4. 목표와 비목표

### 목표

- 분야·운영자 중립적인 설치형 논문 큐레이션 제품을 제공한다.
- 필수 **Core**와 선택적 **Enhancement**를 분리한다.
- Core 리뷰 공급자와 모델은 정확히 하나를 사용자가 선택한다.
- 선택하지 않은 외부 API·과금 기능·배포는 실행하지 않는다.
- 사용자는 각 성공 또는 실패의 근거와 출처를 확인할 수 있다.
- 설정, 자료, 생성물은 설치 로컬 데이터로 소유한다.

### 비목표

- 첫 버전에서 모든 서지관리 시스템을 지원하지 않는다. v1 자료원은 Zotero다.
- 특정 운영자의 코퍼스·생성물·기본 주제 데이터를 제품에 포함하지 않는다.
- 지속적인 upstream 동기화, 병합 또는 호환성 유지는 제공하지 않는다. 일회성 upstream intake는 과거 이력이며 현재 fork만이 향후 기준이다.
- 공급자 또는 모델의 자동 fallback을 제공하지 않는다.
- 기존 거대 운영 스크립트의 flag·모드 호환성을 제품 요구사항으로 보존하지 않는다.
- 기존 코퍼스를 자동 재생성하거나 자동 공개하지 않는다.

## 5. 제품 원칙과 정책

1. **Core 우선:** 논문 한 편의 완결된 큐레이션이 부가기능보다 우선한다.
2. **명시적 선택:** credential의 존재는 기능 선택이 아니다.
3. **정확한 선택과 대체 금지:** Core는 정확히 하나의 선택된 provider/model만 사용하고 실패를 그대로 드러낸다.
4. **로컬 우선:** PDF, 설정, 캐시, DB, 실행 기록, 생성물은 설치 로컬 상태다.
5. **근거 우선:** 성공은 입력, 산출물, 선택된 구현과 fingerprint로 설명 가능해야 한다.
6. **원자적 공개:** 실패하거나 불완전한 실행은 기존 완료 결과를 덮어쓰지 않는다.
7. **분야 중립:** 주제, 기관, taxonomy, 언어 및 프롬프트 스타일은 설치 설정으로 선택한다.
8. **명확한 실패:** 누락, 모호성, 인증·공급자 오류와 검증 오류를 구분해 보인다.
9. **빌드와 배포 분리:** 로컬 생성은 공개 행위가 아니며, 공개 배포는 별도 명시 행위다.

## 6. 사용자에게 보이는 기능과 흐름

### Core 큐레이션

사용자는 Zotero의 범위와 논문을 선택하고, PDF가 명시되었거나 유일할 때만 큐레이션을 실행한다. 제품은 PDF를 읽고, 비어 있지 않은 텍스트를 만들며, 선택한 Core provider/model로 필수 리뷰를 생성한다. 이어 근거 정보와 로컬 논문 페이지를 만들고, 검증된 실행 기록과 함께 완료한다.

Core 성공에는 정확한 논문 식별, 검증된 PDF·텍스트, 비어 있지 않은 필수 리뷰, 열 수 있는 근거 정보와 페이지, 그리고 비밀·논문 전문을 포함하지 않는 실행 기록이 필요하다.

### 선택 기능

그림 후보 추출, Zotero 계층 분류, 클러스터링, 검색 인덱스, 서지 정규화·감사, 중복 탐지 같은 로컬 기능은 기본 비활성화이며 Core 성공 요건이 아니다. 외부 또는 비용 발생 가능 기능(예: figure 검증, embedding, 인용 지표, 요약·insight·timeline·audio, 브라우저 연구, 공개 배포, Zotero 변경)은 `enabled`와 정확한 provider 선택이 모두 있을 때만 실행한다. 선택 기능의 실패는 완료된 Core 결과를 훼손하지 않는다.

### 운영 흐름

사용자는 설치·설정, 상태 확인, 진단, 선택 논문의 갱신, 로컬 빌드, 로컬 제공, 조회·검증·복구, 명시적 공개 배포를 수행한다. 읽기 전용 점검은 데이터를 바꾸지 않고, 복구는 먼저 영향 범위를 미리 보여 준 뒤에만 실제 변경한다.

## 7. 성공 지표

- 새 topic 추가에 필요한 제품 코드 변경 수: 0
- Core 중 선택하지 않은 provider 호출 수: 0
- 선택 provider 실패 후 대체 provider 호출 수: 0
- Core 성공 중 완전한 실행 기록 비율: 100%
- 불완전한 Core 산출물이 완료 페이지를 덮어쓴 횟수: 0
- credential·로컬 경로·생성 코퍼스의 추적 또는 공개 누출 수: 0
- 서로 다른 synthetic topic의 Core 계약 통과율: 100%

## 8. 제품 위험

- **레거시 분해 중 동작 손실:** 사용자가 관찰 가능한 결과를 보존하고, 완료된 전환의 이중 구현을 남기지 않는다.
- **공급자 필수화로 인한 온보딩 실패:** 설치 시 선택·인증·비용 조건을 명확히 확인하며, 실패를 metadata-only 성공으로 낮추지 않는다.
- **범용화 중 유용한 알고리즘 손실:** 범용 알고리즘과 운영 데이터의 소유권을 분리한다.
- **선택 기능의 암묵적 재활성화:** 기능 선택과 credential을 분리하고 호출 자체를 통제한다.
- **기존 코퍼스 훼손:** 새 로컬 작업 공간과 원자적 결과 전환을 사용하며 자동 재생성은 하지 않는다.

## 9. 제품 수용 기준

1. 사용자는 Zotero 범위, 논문, 정확히 하나의 Core provider/model을 명시해 완결된 로컬 논문 페이지를 만들 수 있다.
2. PDF가 없거나 모호하거나 Core provider가 없으면, 성공으로 위장하지 않고 명확히 실패한다.
3. 선택하지 않은 외부 provider와 비용 발생 가능 기능은 호출되지 않는다.
4. 선택한 provider가 실패해도 다른 provider/model로 대체하지 않는다.
5. 여러 논문 실행은 논문별 성공·실패를 보존한다.
6. Enhancement 실패는 성공한 Core 페이지를 보존한다.
7. 로컬 빌드·갱신은 공개 배포를 수행하지 않으며 공개는 별도 명시 행동이다.
8. 사용자 데이터, 비밀, 로컬 경로, PDF와 생성 코퍼스는 제품 저장소 및 공개 산출물에 포함되지 않는다.
